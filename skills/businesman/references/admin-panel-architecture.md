# Эталонная архитектура админ-панелей и внутренних платформ

Этот справочник описывает архитектурный стандарт проектирования внутренних систем, панелей управления (Backoffice / Admin Panel) и SaaS-дашбордов с соблюдением правил HZ Ecosystem (`hz-admin-charts`, `hz-forms-as-modals`, `hz-theme-palette`), требований корпоративной безопасности и высокой информационной плотности.

---

## 1. Базовые правила HZ Ecosystem для админ-панелей

1. **Графика с первого дня (`hz-admin-charts`):**
   - Главная страница раздела или модуль управления обязан начинаться с аналитического блока: ключевые KPI-метрики + графики динамики.
   - Обязателен интерактивный переключатель периодов: **День / Неделя / Месяц / Квартал / Год** с динамическим пересчетом всех графиков и сравнительных дельт (Vs Previous Period).
2. **Формы = модальные окна (`hz-forms-as-modals`):**
   - Любое создание сущности, редактирование параметров, смена статуса или опасное действие выполняется строго через модальные окна (Dialog / Modal) или выдвижные боковые панели (Sheet / Drawer), а не через переход на отдельную пустую страницу.
   - Модалка должна иметь захват фокуса (Focus Trap), закрытие по `Escape` и клику вне области (с подтверждением при наличии несохраненных данных).
3. **Палитра темы проекта (`hz-theme-palette`):**
   - Запрещено использовать жестко закодированные цвета (`#0f172a`, `slate-950`).
   - Использовать строго системные семантические токены темы: `bg-background`, `bg-card`, `bg-muted`, `text-foreground`, `text-muted-foreground`, `border-border`, `bg-primary`, `bg-destructive`.

## 2. Анатомия интерфейса и компонентная сетка

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ Header: [Tenant Switcher] [Global Search ⌘K]   [Live Status] [🔔] [Avatar] │
├──────────────┬──────────────────────────────────────────────────────────────┤
│ Sidebar      │ Main Content Area                                            │
│              │ 1. Breadcrumbs & Page Header + [Primary Action Modal Button] │
│ • Dashboard  ├──────────────────────────────────────────────────────────────┤
│ • Analytics  │ 2. KPI Cards + Interactive Charts (Day/Week/Month/Qtr/Year)  │
│ • Users      ├──────────────────────────────────────────────────────────────┤
│ • Billing    │ 3. Filter Bar (Search, Facets, Date Range, Column Picker)   │
│ • Audit Logs ├──────────────────────────────────────────────────────────────┤
│ • Settings   │ 4. Enterprise Data Grid (Virtualized, Bulk Actions, Drawer)  │
│              ├──────────────────────────────────────────────────────────────┤
│ [Collapse]   │ 5. Pagination Bar (Items per page, Page jumpers, Total count)│
└──────────────┴──────────────────────────────────────────────────────────────┘
```

### 2.1. Верхняя панель (Header)
- **Tenant Switcher:** Переключение между организациями/филиалами с сохранением текущего контекста страницы.
- **Command Palette (`Cmd + K`):** Глобальный быстрый поиск по клиентам, заказам, страницам настроек и быстрым действиям.
- **Индикатор живого соединения (Live Connection State):** Зеленая точка «Подключено (SSE/WebSocket)», предупреждение «Переподключение...», если веб-сокет разорван.
- **Колокольчик уведомлений:** Счетчик непрочитанных критических событий с выпадающим списком.
- **Профиль:** Имя, роль, кнопка включения компактного режима таблицы и безопасный выход (Logout).

### 2.2. Навигация (Sidebar)
- Группировка по доменам: Основное, Бизнес-операции, Финансы, Безопасность и Аудит, Системные настройки.
- Счетчики бейджей для элементов, требующих внимания (например, «Заявки на вывод: 4»).
- Компактный режим сворачивания (Icon-only) для экономии экранного пространства на ноутбуках.

## 3. Аналитический блок и KPI-карты (`hz-admin-charts`)

### 3.1. Карточки метрик (KPI Cards)
Каждая карточка содержит:
1. Заголовок метрики (например, «Выручка MRR», «Активные тенанты», «Конверсия в оплату»).
2. Текущее значение с форматированием валют и разделителями тысяч.
3. Дельта к предыдущему аналогичному периоду с цветовой маркировкой:
   - `+14.2%` (зеленый бейдж, стрелка вверх) при росте позитивной метрики.
   - `-3.1%` (красный бейдж, стрелка вниз) при падении.
4. Микро-график тренда (Sparkline SVG) за последние 30 точек без осей для мгновенного считывания динамики.

### 3.2. Графики и временной скруббер
- **Линейный график с областями (Area Chart):** Динамика выручки и регистраций во времени. Тултип отображает точные числа при наведении курсора.
- **Гистограмма (Bar Chart):** Сравнение объемов по когортам или каналам привлечения.
- **Круговая диаграмма / Donut:** Распределение тарифов или типов ошибок.
- **Интерактивные переключатели метрик:** Возможность скрывать или накладывать серии данных кликом по легенде.

## 4. Движок таблиц и работа с данными (Enterprise Data Grid)

Таблица — главный рабочий инструмент оператора. Она обязана выдерживать миллионы строк без зависания браузера.

### 4.1. Серверная обработка (Server-Side Pipeline)
Все операции выполняются на стороне сервера через параметры API:
`GET /api/admin/users?page=1&limit=50&sort=created_at:desc&search=alex&status=active&created_after=2026-01-01`
- **Пагинация:** Выбор лимита (10 / 25 / 50 / 100 строк), курсорная пагинация (Keyset Pagination) для больших объемов данных.
- **Сортировка:** Клик по заголовку колонки переключает `ASC` $\to$ `DESC` $\to$ `None`. Возможность мульти-сортировки с зажатым `Shift`.
- **Поиск:** Дебаунс ввода (300 мс) перед отправкой запроса на сервер.

### 4.2. Продвинутые фильтры (Faceted Filtering)
- Фильтры оформляются компактными чипами-пилюлями (Filter Pills): `[Статус: Активен ×]`, `[Тариф: Enterprise ×]`.
- Выбор диапазона дат с пресетами: «Сегодня», «Вчера», «Последние 7 дней», «Этот месяц», «Произвольный».
- Кнопка «Сбросить все фильтры» появляется только при наличии активных фильтраций.

### 4.3. Управление колонками и виртуализация
- **Селектор колонок (Column Visibility):** Выпадающий список чекбоксов для скрытия ненужных столбцов. Сохранение конфигурации в `localStorage` пользователя.
- **Закрепленные колонки (Sticky Columns):** Колонка с чекбоксом выбора и колонка с кнопками действий (`Actions`) зафиксированы по краям при горизонтальном скролле.
- **Виртуализация DOM:** При рендере более 100 строк в DOM монтируются только видимые на экране элементы (`@tanstack/react-virtual`).

### 4.4. Массовые операции (Bulk Actions)
- Чекбокс в шапке: «Выбрать все на странице» + всплывающая подсказка «Выбрать все 4 820 записей, подходящих под фильтр».
- Плавающая панель действий (Floating Bar) при выборе 1+ строк:
  - «Экспортировать выбранные в CSV/XLSX» (через асинхронную задачу в очереди).
  - «Изменить статус» (открытие модального окна).
  - «Удалить выбранные» (модальное окно с жестким предупреждением).

### 4.5. Детальный просмотр (Row Drawer / Sheet)
- Клик по строке открывает выдвигающуюся справа панель (Drawer / Slide-over) с полной информацией о сущности, историей изменений и связанными объектами без ухода со страницы таблицы.

## 5. Безопасность, аудит и разграничение доступа в админке

### 5.1. Мультиарендная матрица прав (Tenant RBAC)
Права структурируются в формате `Организация : Ресурс : Действие`:
```typescript
type Permission = 
  | 'users:read' | 'users:write' | 'users:delete'
  | 'billing:view_invoices' | 'billing:refund'
  | 'system:audit_logs' | 'system:manage_keys';
```
- Проверка прав выполняется на сервере в middleware перед вызовом контроллера. Клиентский код лишь скрывает кнопки в UI для исключения визуального шума.

### 5.2. Иммутабельный аудит-лог (Audit Trail)
Каждое изменение в админ-панели обязано логироваться:
```json
{
  "event_id": "aud_01J8F...",
  "timestamp": "2026-10-20T17:55:00Z",
  "actor": {
    "user_id": "usr_admin_123",
    "email": "lead@hzcompany.ru",
    "ip_address": "198.51.100.42",
    "user_agent": "Mozilla/5.0..."
  },
  "action": "billing.subscription.discount_applied",
  "resource": {
    "type": "tenant",
    "id": "ten_987",
    "name": "Acme Corp"
  },
  "diff": {
    "before": { "discount_percent": 0 },
    "after": { "discount_percent": 25 }
  },
  "reason": "Approved by CFO via ticket #4812"
}
```

### 5.3. Предохранители для опасных действий (Destructive Actions Guard)
Для необратимых операций (удаление базы, сброс ключей шифрования, блокировка крупного клиента):
1. Обязательное открытие специального модального окна (`hz-forms-as-modals`).
2. Требование ввести вручную точное имя удаляемого ресурса (например, напечатать `ten_987/Acme Corp`).
3. Повторный запрос пароля администратора или 6-значного кода MFA (Step-Up Authentication).
4. Обязательное текстовое поле: «Причина выполнения операции» (сохраняется в аудит-лог).

### 5.4. Режим безопасного входа под пользователем (Impersonation Mode)
- Доступен только ролям `SuperAdmin` и `Senior Support`.
- Требует указания номера тикета в техподдержку.
- При активации:
  - Вверху экрана фиксируется неизгладимый ярко-красный баннер: `ВЫ РАБОТАЕТЕ В РЕЖИМЕ ПЕРЕВОПЛОЩЕНИЯ: [email] | [Кнопка: Завершить сессию]`.
  - Запрещены любые опасные действия (смена пароля, удаление учетной записи).
