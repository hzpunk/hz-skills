# 100 Практик, Архитектурных Паттернов и Стандартов Frontend-разработчика

Этот справочник содержит 100 прикладных инструментов, стандартов архитектуры (RSC, FSD), техник оптимизации Core Web Vitals (LCP, INP, CLS), управления состоянием (TanStack Query, Zustand), безопасности (XSS/CSP) и тестирования для ведущего инженера фронтенда (Staff / Principal Frontend Engineer).

---

## Раздел I: Архитектура рендеринга и современные мета-фреймворки (1–13)

### 1. Серверные компоненты React 19 (React Server Components, RSC)
- Четкое разделение ответственности:
  - Серверные компоненты (по умолчанию в Next.js App Router): прямой доступ к БД/API, нулевое влияние на вес клиентского JS-бандла, безопасное использование секретов.
  - Клиентские компоненты (`'use client'`): только там, где требуются интерактивность (`onClick`, `onChange`), хуки состояния (`useState`, `useEffect`) или доступ к браузерным API (`window`, `localStorage`).
- Правило: смещать границу `'use client'` как можно ниже по дереву компонентов (Leaf-level components).

### 2. Серверные экшены с валидацией (Server Actions `'use server'`)
- Выполнение мутаций на сервере без необходимости ручного создания API-роутов.
- Обязательная валидация входных данных через Zod-схемы на сервере:
  ```typescript
  'use server'
  export async function submitLead(formData: FormData) {
    const parsed = leadSchema.safeParse(Object.fromEntries(formData));
    if (!parsed.success) return { error: parsed.error.flatten() };
    await db.leads.create({ data: parsed.data });
    revalidatePath('/dashboard');
  }
  ```
- Встроенная защита от CSRF благодаря механизмам проверки Origin и Host мета-фреймворком.

### 3. Потоковый рендеринг и границы Suspense (Streaming SSR)
- Устранение проблемы «всё или ничего» при серверном рендеринге:
  - Медленные запросы (например, аналитические графики) оборачиваются в `<Suspense fallback={<ChartSkeleton />}>`.
  - Быстрая оболочка страницы (навигация, заголовок) отдается браузеру мгновенно (TTFB $<100$ мс), а медленный блок досылается в том же HTTP-соединении чанком HTML по мере готовности.

### 4. Архитектура Feature-Sliced Design (FSD 2.1)
- Строгая модульная структура для средних и крупных кодовых баз:
  - Слои (снизу вверх): `shared` $\to$ `entities` $\to$ `features` $\to$ `widgets` $\to$ `pages` $\to$ `app`.
  - Правило направленности импортов: модуль может импортировать только то, что находится на слоях ниже него. Модули на одном слое не могут импортировать друг друга напрямую (только через агрегацию на верхнем уровне).

### 5. Ликвидация каскадных запросов (Waterfalls Elimination)
- Категорический запрет на цепочки последовательных запросов на клиенте:
  `fetchUser()` $\to$ ждем $\to$ `fetchOrders(userId)` $\to$ ждем $\to$ `fetchDetails()`.
- Решение: выборка данных на сервере параллельно через `Promise.all([getUser(), getOrders()])` или предварительная загрузка связанных данных одним JOIN-запросом.

### 6. Режимы генерации страниц: SSG, ISR и Dynamic SSR
- Осознанный выбор стратегии для каждого маршрута:
  - **Static Site Generation (SSG / `output: 'export'`):** Маркетинговые лендинги и блоги собираются в чистый статический HTML/CSS один раз при сборке. Идеальная скорость, \$0 затрат на сервер.
  - **Incremental Static Regeneration (ISR):** Страницы каталога генерируются статически и фоново обновляются по таймеру (`revalidate = 3600`) без пересборки всего сайта.
  - **Dynamic SSR:** Персонализированные закрытые кабинеты с рендерингом на лету.

### 7. View Transitions API: Нативные бесшовные переходы
- Использование нативного браузерного API `document.startViewTransition()` для плавного анимирования элементов между страницами или состояниями без тяжелых JS-библиотек (размер $0$ КБ бандла).

### 8. Острова архитектуры (Islands Architecture)
- Паттерн для контентных сайтов (Astro): страница рендерится как 100% статический чистый HTML, а интерактивные виджеты (например, калькулятор или поиск) изолируются в виде «островов» с ленивой гидратацией (`client:visible` или `client:idle`).

### 9. Предзагрузка данных на основе намерений (Intent-based Prefetching)
- Роутер предзагружает код страницы и данные в момент, когда пользователь наводит курсор на ссылку (`onMouseEnter`) или когда ссылка появляется в зоне видимости (Intersection Observer). При клике переход происходит мгновенно (0 мс задержки).

### 10. Полноценная поддержка Server-Sent Events (SSE) для LLM и живых лент
- Реализация потокового чтения стрима через `ReadableStream` и `TextDecoderStream` на клиенте с автоматическим переподключением при разрыве связи и экспоненциальным бэкоффом.

### 11. Edge Middleware для легкой маршрутизации и A/B тестов
- Выполнение логики проверки геолокации, редиректов, проверки токена авторизации и разделения A/B потоков на пограничных узлах (Edge Nodes) за $<10$ мс до основного рендеринга.

### 12. Микрофронтенды: Когда избегать и когда внедрять
- Закон CTO & Frontend Lead: микрофронтенды (Module Federation) оправданы **только** при наличии 5+ полностью независимых команд разработки с разными циклами релизов. Во всех остальных случаях микрофронтенды создают колоссальный оверхед зависимостей и замедляют загрузку.

### 13. Изоляция контекстов и избегание глобального Root Provider Hell
- Отказ от оборачивания всего приложения в 15 глобальных React Context Providers. Контексты локализуются строго вокруг тех поддеревьев, которым они реально необходимы.

## Раздел II: Производительность и оптимизация Core Web Vitals (14–25)

### 14. Оптимизация LCP (Largest Contentful Paint $< 2.5$ сек)
- Главный элемент первого экрана (Hero Image или Заголовок):
  - Для изображений: атрибут `priority` (в Next.js) или `fetchpriority="high"`, формат AVIF/WebP, запрет ленивой загрузки (`loading="eager"`).
  - Предзагрузка критических шрифтов через `<link rel="preload" as="font" type="font/woff2" crossorigin>`.
  - Устранение серверных задержек первого байта (TTFB $< 300$ мс).

### 15. Оптимизация INP (Interaction to Next Paint $< 200$ мс)
- Замена устаревшего FID на INP: оптимизация отклика на клики, тапы и нажатия клавиш.
- Длинные задачи (Long Tasks $>50$ мс) разбиваются на микро-задачи с помощью современного `scheduler.yield()` или `setTimeout(..., 0)`, давая браузеру возможность отрисовать кадр между вычислениями.

### 16. Ликвидация CLS (Cumulative Layout Shift $< 0.1$)
- Полное устранение сдвигов верстки при загрузке:
  - 100% изображений и видео имеют явно заданные атрибуты `width` и `height` или CSS свойство `aspect-ratio`.
  - Резервирование точного пространства под динамические баннеры и рекламу.
  - Подключение кастомных веб-шрифтов с параметром `font-display: optional` или точной настройкой метрик замещающего шрифта (`size-adjust`, `ascent-override`) для исключения скачков текста.

### 17. 120fps анимации: Только композиторные свойства
- Категорический запрет анимировать свойства, вызывающие пересчет геометрии (Layout / Reflow) и перерисовку (Paint): `width`, `height`, `top`, `left`, `margin`, `padding`.
- Анимация осуществляется **исключительно** через `transform` (перемещение, масштабирование) и `opacity`.
- Аппаратное ускорение через `transform: translateZ(0)` или `will-change: transform`. Запрет анимирования тяжелых CSS-фильтров (`filter: blur(...)`) на крупных DOM-узлах.

### 18. Бюджет размера бандла (Bundle Size Budget $\le 100$ КБ)
- Жесткий лимит: суммарный начальный объем исполняемого JavaScript на маршрут не должен превышать 100 КБ в сжатом виде (gzipped).
- Автоматический контроль в CI через `@next/bundle-analyzer` или Size Limit: билд падает при превышении бюджета.

### 19. Агрессивный Tree-Shaking и аудит зависимостей
- Указание `"sideEffects": false` в `package.json`.
- Полный запрет тяжелых библиотек-мастодонтов:
  - Замена `moment.js` (300 КБ) на нативный JavaScript `Intl` или `dayjs`/`date-fns`.
  - Замена `lodash` на точечные импорты `lodash-es` или современные нативные методы ES2024 (`Array.prototype.toSorted`, `Object.groupBy`).

### 20. Динамический код-сплиттинг (Dynamic Imports)
- Ленивая загрузка компонентов, не нужных для первого экрана:
  - Тяжелые графики (Chart.js / Recharts), модальные окна, PDF-просмотрщики и редакторы текста загружаются через `dynamic(() => import('./HeavyModal'), { ssr: false })` строго в момент клика пользователя.

### 21. Виртуализация длинных списков (Virtual Scrolling)
- При отображении списков более 100 элементов (таблицы, бесконечные ленты, каталоги): использование TanStack Virtual. В DOM-дереве физически существует ровно столько DOM-узлов, сколько помещается на экране (15–20 штук), что гарантирует 60–120fps скролл при любом размере выборки.

### 22. React Compiler и ликвидация паразитных ререндеров
- Внедрение React Compiler (React 19) для автоматической глубокой мемоизации компонентов и значений.
- В кодовой базе React 18: осознанное использование `React.memo`, `useCallback` и `useMemo` вокруг тяжелых вычислительных блоков и стабильных ссылок на функции.

### 23. Вынос тяжелых вычислений в Web Workers
- Парсинг CSV/Excel на 100 000 строк, клиентская криптография, компрессия изображений на Canvas и сортировка многомерных массивов выносятся в отдельный фоновый поток (Web Worker) через `comlink`, исключая зависание главного UI-потока.

### 24. Оптимизация изображений: AVIF-First
- Раздача графики в ультрасовременном формате AVIF (сжатие на 30–50% эффективнее WebP при сохранении качества). Настройка адаптивных `sizes` в компоненте `<Image />`, предотвращающая загрузку картинок разрешением 4K на экран смартфона.

### 25. Service Worker и прекеширование статики
- Внедрение Workbox для PWA: кэширование неизменяемых шрифтов, CSS и иконок по стратегии `CacheFirst`. Мгновенная загрузка при повторных визитах и поддержка базового offline-состояния приложения.

## Раздел III: Управление состоянием и серверный кэш (26–38)

### 26. Разделение Server State и Client State
- Главное архитектурное правило: **Данные с бэкенда — это не стейт, это удаленный кэш**.
- Отказ от дублирования ответов API в Redux/Zustand. Для работы с данными сервера используется TanStack Query (React Query) или SWR. Клиентский стейт хранит строго UI-состояние (открыта ли модалка, выбранная тема, фокус).

### 27. TanStack Query: Автоматическая дедупликация и Stale-While-Revalidate
- Все запросы к API кэшируются по структурированным ключам (`queryKey: ['orders', { status: 'active' }]`):
  - Автоматическая дедупликация: 5 компонентов на странице, запрашивающих одного и того же пользователя, отправляют ровно 1 сетевой запрос.
  - Фоновое обновление данных при возврате фокуса на вкладку браузера (`refetchOnWindowFocus: true`).

### 28. Легковесный клиентский стейт на Zustand
- Использование Zustand вместо громоздкого Redux:
  - Минимальный размер ($<1.5$ КБ).
  - Отсутствие необходимости оборачивать приложение в Providers.
  - Использование атомарных селекторов (`const isOpen = useModalStore(s => s.isOpen)`), исключающее ререндер компонента при изменении других полей хранилища.

### 29. URL как единственный источник истины (URL State)
- Все фильтры, сортировки, поисковые запросы, вкладки и номера страниц хранятся в query-параметрах адресной строки браузера (`?status=active&page=2&sort=date`):
  - Пользователь может скопировать ссылку, отправить коллеге, обновить страницу или нажать «Назад» и получить ровно то же состояние интерфейса.
  - Использование библиотеки `nuqs` для типобезопасного парсинга параметров.

### 30. Атомарное состояние: Jotai / Nanostores
- Для микро-интерактивностей с высокой частотой обновления (аудиоплееры, рисовалки, сложные канбан-доски): использование атомов Jotai. Обновление одного атома перерисовывает строго один ассоциированный DOM-узел без затрагивания соседей.

### 31. Синхронизация вкладок через BroadcastChannel API
- Если пользователь разлогинился или изменил тему оформления в одной вкладке браузера — все остальные открытые вкладки мгновенно синхронизируют свое состояние через нативный `BroadcastChannel` без необходимости сетевого поллинга.

### 32. Машины состояний (State Machines / XState)
- Для сложных ветвящихся процессов (оформление заказа, многофакторная авторизация, кредитный калькулятор): проектирование конечных автоматов с явным списком состояний и разрешенных переходов. Математически исключает невозможные состояния (например, одновременное состояние `isLoading: true` и `isSuccess: true`).

### 33. Оптимистичные обновления (Optimistic UI: `useOptimistic`)
- При лайке, отправке комментария или смене статуса задачи интерфейс обновляется мгновенно на клиенте ($<10$ мс). В фоне уходит сетевой запрос. В случае сетевой ошибки интерфейс плавно откатывается назад с показом информативного Toast-уведомления.

### 34. Формы на React Hook Form + Zod
- Категорический отказ от хранения значений каждого символа формы в `useState` (что вызывает 50 ререндеров формы при наборе слова).
- Использование неконтролируемых компонентов через React Hook Form: 60fps скорость ввода на слабых устройствах, валидация по Zod-схеме на лету.

### 35. Нормализация клиентского кэша
- Хранение сложных реляционных данных в нормализованном виде по их `id` (`{ byId: { '1': {...} }, allIds: ['1'] }`), исключающее рассинхронизацию данных, когда имя одного и того же пользователя обновилось в профиле, но осталось старым в шапке и комментариях.

### 36. Безопасная работа с локальным хранилищем (IndexedDB via idb-keyval)
- Отказ от синхронного `localStorage` для хранения больших массивов данных (он блокирует главный поток браузера). Использование асинхронной базы данных IndexedDB для кэширования черновиков и оффлайн-данных.

### 37. Устранение гонок запросов (Race Conditions Handling)
- Если пользователь быстро кликает по фильтрам: автоматическая отмена предыдущего незавершенного HTTP-запроса через `AbortController`, гарантирующая, что медленный старый ответ не перезапишет свежие данные.

### 38. Автосохранение черновиков с Debounce
- Сохранение введенного пользователем текста в локальный кэш через `debounce(fn, 500)`: защита от потери данных при случайном закрытии вкладки или сбое соединения.

## Раздел IV: Стилизация, Дизайн-системы и токены (39–51)

### 39. Семантические CSS-переменные (hz-theme-palette rule)
- Категорический запрет на использование жестко захардкоженных цветов в коде компонентов (`bg-slate-900`, `text-gray-950`).
- 100% стилизации строится на системных семантических классах темы: `bg-background`, `text-foreground`, `bg-card`, `bg-muted`, `border-border`, `bg-primary`, обеспечивающих корректную работу светлой, темной и контрастной тем.

### 40. Headless UI компоненты (Radix UI / Base UI)
- Использование проверенных, доступных по умолчанию (a11y-ready) библиотек без стилей: Radix UI, React Aria. Вся логика работы фокуса, клавиш клавиатуры, ARIA-атрибутов и позиционирования порталов уже решена, а визуал оформляется кастомным Tailwind CSS.

### 41. Физика спринговых анимаций (Framer Motion / Motion)
- Запрет на использование линейных или топорных `ease-in-out` переходов для движения интерфейсных объектов.
- Использование физических пружин (Spring Physics: `type: "spring", stiffness: 350, damping: 25`), создающих естественное, отзывчивое, тактильно приятное ощущение интерфейса.

### 42. Бесшовное переключение тем (Zero-FOUC Dark Mode)
- Встраивание крошечного синхронного инлайн-скрипта в `<head>` документа, который считывает системную тему (`prefers-color-scheme`) или `localStorage` до отрисовки первого байта DOM, исключая раздражающую белую вспышку при загрузке темного сайта.

### 43. Адаптивная типографика на `clamp()`
- Отказ от десятка медиа-запросов для изменения размера шрифта. Использование одной формулы:
  `font-size: clamp(2rem, 1.5rem + 2.5vw, 3.5rem);`
  Размер шрифта плавно и непрерывно масштабируется между экраном смартфона и широким монитором 4K.

### 44. Контейнерные запросы (CSS Container Queries `@container`)
- Переход от медиа-запросов экрана к запросам контейнера: карточка товара сама решает, как ей выглядеть (в виде горизонтальной строки или вертикальной плитки) в зависимости от ширины того блока, в который ее поместили (в узкий сайдбар или в широкую сетку).

### 45. Современный селектор `:has()` в CSS
- Стилизация родительского элемента на основе состояния его потомков без использования JavaScript:
  `figure:has(figcaption) { border-bottom: 2px solid var(--border); }`
  `form:has(input:invalid) button[type="submit"] { opacity: 0.5; }`

### 46. Масштабируемая шкала слоев (Z-Index Tokens)
- Полная ликвидация хаоса со случайными числами `z-index: 999999`. Внедрение строгой иерархии CSS-переменных:
  `--z-negative: -1; --z-elevated: 1; --z-dropdown: 10; --z-sticky: 20; --z-drawer: 30; --z-modal: 40; --z-popover: 50; --z-toast: 100;`

### 47. Цветовое пространство OKLCH
- Использование современного цветового формата OKLCH для создания дизайн-токенов: гарантирует одинаковую воспринимаемую глазом яркость и контрастность при смене цветового оттенка, исключая грязные или блеклые цвета в темной теме.

### 48. Исключение скачков шрифта (Font Metric Overrides)
- Использование `@font-face` дескрипторов `size-adjust`, `ascent-override` и `descent-override` для системного резервного шрифта (Arial/Roboto), подгоняющих его физические размеры ровно под кастомный шрифт до его загрузки.

### 49. Оптимизация тяжелых графических эффектов (Canvas / WebGL)
- Если на фоне используется интерактивный холст (тушь, частицы):
  - Обработка событий мыши через `requestAnimationFrame` с троттлингом до частоты обновления экрана.
  - Использование пассивных слушателей `{ passive: true }`.
  - Обязательная очистка таймеров, контекстов и удаление слушателей при размонтировании компонента (`useEffect cleanup`).

### 50. Утилита объединения классов (`cn` helper)
- Обязательное использование связки `clsx` и `tailwind-merge` для безопасного динамического склеивания классов без конфликтов специфичности стилей Tailwind:
  ```typescript
  import { clsx, type ClassValue } from 'clsx';
  import { twMerge } from 'tailwind-merge';
  export function cn(...inputs: ClassValue[]) { return twMerge(clsx(inputs)); }
  ```

### 51. Защита от переполнения текстом (Truncation & Line Clamp)
- Для всех карточек с динамическим контентом: обязательное использование `line-clamp-2` или `truncate` с всплывающей подсказкой (Tooltip) полного текста при наведении, предотвращающее поломку верстки при длинных фамилиях или названиях.

## Раздел V: Доступность (a11y) и семантика (52–63)

### 52. Инспекция дерева доступности (Accessibility Tree Audit)
- Регулярный аудит доступности через Chrome DevTools / Playwright axe-core: проверка того, как страница видится вспомогательными технологиями, проверка доступных имен (`accessible name`) у всех интерактивных элементов.

### 53. Семантическая верстка на нативных элементах HTML5
- Запрет кликабельных `<div>` и `<span>` с `onClick`.
- Для перехода по ссылке — строго `<a>`.
- Для совершения действия внутри страницы — строго `<button type="button">`.
- Для модальных окон — нативный тег `<dialog>` с автоматическим управлением фокусом и поддержкой клавиши `Esc`.

### 54. Циклический захват фокуса в модалках (Focus Trap)
- При открытии любого диалога или шторки:
  - Фокус автоматически перемещается на первый интерактивный элемент внутри модалки.
  - Нажатие `Tab` на последнем элементе переносит фокус на первый элемент модалки, не позволяя пользователю случайно уйти на невидимые фоновые элементы страницы.
  - При закрытии модалки фокус возвращается ровно на ту кнопку, которая ее открыла.

### 55. Визуальный индикатор клавиатурного фокуса (`:focus-visible`)
- Стили фокуса показываются только тогда, когда пользователь перемещается с клавиатуры, и скрываются при клике мышью:
  `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2`

### 56. Связывание подписей и полей ввода форм
- Каждое поле ввода обязано иметь программную связь со своим текстовым описанием через `<label htmlFor="email">` и `<input id="email">`.
- Сообщения об ошибках связываются с полем через `aria-describedby="email-error"` и атрибут `aria-invalid="true"`.

### 57. Доступность кнопок-иконок (`.sr-only`)
- Если кнопка содержит только визуальную SVG-иконку (например, крестик закрытия или иконку лупы):
  - Наличие скрытого текста: `<span className="sr-only">Закрыть окно</span>`.
  - Или атрибут `aria-label="Закрыть окно"`.
  - На самой SVG-иконке обязателен атрибут `aria-hidden="true"`, чтобы скринридер не зачитывал бессмысленные теги paths.

### 58. Динамические живые регионы (ARIA Live Regions)
- Для асинхронных уведомлений (Toast messages, счетчик результатов поиска, статус автосохранения): использование контейнера с атрибутом `aria-live="polite" aria-atomic="true"`, озвучивающего новые события пользователям скринридеров без прерывания их текущих действий.

### 59. Полная поддержка `prefers-reduced-motion`
- Во всех анимациях Framer Motion и CSS-переходах: автоматическое отключение движения при системном запросе пользователя на минимизацию анимаций:
  ```typescript
  const shouldReduceMotion = useReducedMotion();
  const transition = shouldReduceMotion ? { duration: 0 } : { type: 'spring', damping: 25 };
  ```

### 60. Минимальный размер интерактивных зон ($44 \times 44$ px)
- Все кнопки, чекбоксы и переключатели обязаны иметь активную область нажатия не менее $44 \times 44$ пикселей на тач-устройствах (при необходимости расширяется невидимым псевдоэлементом `::before`).

### 61. Доступные структуры таблиц данных
- Таблицы верстаются с использованием тегов `<caption>`, `<thead>`, `<tbody>`, `<th scope="col">` и `<th scope="row">`, позволяя незрячим пользователям понимать, к какой колонке и строке относится конкретное значение ячейки.

### 62. Цветовая независимость информации
- Любой статус (ошибка, предупреждение, успех) обозначается не только цветом (красный/зеленый), но и сопровождается понятной текстовой меткой и узнаваемой иконкой.

### 63. Автоматизированный a11y-тест в CI/CD
- Запуск `@axe-core/playwright` в рамках сквозных E2E-тестов: ни один релиз не попадает в продакшн, если страница содержит нарушения доступности уровня WCAG 2.2 AA.

## Раздел VI: Безопасность фронтенда (Client-Side AppSec) (64–76)

### 64. Полное предотвращение XSS (Cross-Site Scripting)
- Запрет неэкранированного вывода пользовательских данных.
- Категорический запрет `dangerouslySetInnerHTML` без предварительной строгой очистки через библиотеку DOMPurify с белым списком разрешенных тегов.

### 65. Строгая политика безопасности контента (Content Security Policy, CSP)
- Настройка заголовков сервера:
  `Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-...'; object-src 'none'; frame-ancestors 'none';`
- Полный запрет `'unsafe-inline'` и `'unsafe-eval'`, блокирующий выполнение внедренного вредоносного JS-кода в браузере.

### 66. Безопасное хранение токенов авторизации
- Отказ от хранения JWT access/refresh токенов в `localStorage` или `sessionStorage` (они мгновенно воруются любой уязвимой npm-библиотекой через XSS).
- Хранение сессионных идентификаторов строго в cookies с флагами `HttpOnly; Secure; SameSite=Lax`.

### 67. Безопасность внешних ссылок
- Все ссылки, открывающиеся в новой вкладке (`target="_blank"`), обязаны содержать атрибуты:
  `rel="noopener noreferrer"`
  Исключает уязвимость Tabnabbing (когда открытая внешняя страница подменяет адрес исходной вкладки через `window.opener`).

### 68. Защита от протокола `javascript:` в ссылках
- При динамическом выводе ссылок от пользователей (в профилях или комментариях): обязательная валидация протокола. Блокировка ссылок вида `javascript:alert(1)` или `data:text/html,...`. Разрешены строго `https:`, `http:`, `mailto:`, `tel:`.

### 69. Сканирование зависимостей (Dependency Supply Chain Audit)
- Внедрение Socket.dev и `npm audit` в пайплайн разработки: обнаружение библиотек, содержащих сетевой шпионаж, отправку переменных окружения или замаскированные майнеры в `node_modules`.

### 70. Защита от утечки секретных переменных окружения
- Строгий аудит: переменные без префикса `NEXT_PUBLIC_` никогда не попадают в клиентский бандл. Проверка исходников сборки на случайное попадание приватных API-ключей и паролей.

### 71. Subresource Integrity (SRI) для CDN-скриптов
- При подключении сторонних шрифтов или скриптов аналитики со сторонних серверов: указание криптографического хэша `integrity="sha384-..."`. Браузер заблокирует выполнение скрипта, если CDN был взломан и файл подменен.

### 72. Безопасная загрузка файлов (Safe File Uploads)
- Проверка размера файла и MIME-типа на клиенте до начала отправки.
- Защита от SVG-XSS: загружаемые пользователями SVG-файлы очищаются или отображаются через тег `<img>` (где исполнение внутренних скриптов заблокировано браузером), а не встраиваются инлайном в DOM.

### 73. Защита от Clickjacking
- Установка HTTP-заголовков `X-Frame-Options: DENY` и CSP `frame-ancestors: 'none'`, запрещающих встраивание вашего веб-приложения в скрытый `iframe` на фишинговых сайтах.

### 74. Очистка состояния при выходе из аккаунта (Logout Sanitization)
- При разлогине: принудительная очистка всех кэшей TanStack Query (`queryClient.clear()`), сброс Zustand-хранилищ, очистка сессионных кук и IndexedDB, гарантирующая, что следующий пользователь того же компьютера не увидит чужие данные.

### 75. 5-уровневая анти-бот защита веб-форм (hz-forms-anti-bot standard)
- Обязательный стандарт для всех публичных форм:
  1. Скрытое поле-приманка (Honeypot).
  2. Проверка времени заполнения (человек не заполняет форму быстрее 3–5 секунд).
  3. Временный крипто-токен валидации.
  4. Защита от повторной отправки (Submit Debounce).
  5. Корректные `aria-` атрибуты без спама ложных ошибок.

### 76. Санитайзинг экспортируемых в CSV пользовательских данных
- Экранирование спецсимволов `=`, `+`, `-`, `@` в начале текстовых полей перед формированием клиентского CSV-файла (защита от Formula Injection при открытии в Microsoft Excel).

## Раздел VII: Тестирование, надежность и качество кода (77–88)

### 77. Пирамида тестирования фронтенда
- Баланс усилий:
  - **Unit-тесты (Vitest):** 70% тестов — чистые функции, утилиты, парсеры данных, кастомные хуки.
  - **Component / Integration (React Testing Library):** 20% тестов — взаимодействие компонентов, поведение форм, состояния загрузки.
  - **E2E-тесты (Playwright):** 10% тестов — сквозные критические бизнес-сценарии (вход $\to$ оформление $\to$ оплата).

### 78. Тестирование по поведению (User-Centric Testing)
- Тесты пишутся так, как интерфейсом пользуется человек:
  - Запрет поиска элементов по CSS-классам или внутренним ID.
  - Поиск по доступным ролям: `screen.getByRole('button', { name: /сохранить/i })`.
  - Поиск по плейсхолдерам и текстовым подписям: `screen.getByLabelText(/электронная почта/i)`.

### 79. Mock Service Worker (MSW 2.0)
- Перехват сетевых запросов на уровне Service Worker API:
  - Одинаковые моки API используются и для Unit-тестов в Vitest, и для E2E-тестов в Playwright, и для локальной разработки без запущенного бэкенда.
  - Тестирование сетевых сбоев (500 Internal Error, задержка 3 секунды, оффлайн) в 1 строчку кода.

### 80. Границы ошибок (React Error Boundaries)
- Изоляция потенциально опасных компонентов (сложные интерактивные графики, сторонние виджеты):
  - При возникновении runtime-ошибки падает строго один изолированный блок, показывая аккуратный интерфейс ошибки с кнопкой «Попробовать снова». Вся остальная страница и навигация продолжают стабильно работать.

### 81. Трекинг ошибок в продакшне (Sentry Integration)
- Автоматический сбор необработанных исключений с отправкой полного контекста: операционная система, браузер, шаги пользователя до ошибки (Breadcrumbs) и стек вызовов.
- Обязательная автоматическая загрузка Source Maps в Sentry во время сборки и их немедленное удаление из публичной раздачи.

### 82. 5 состояний каждого интерфейсного компонента
- Каждый компонент, загружающий данные, обязан явно проектироваться и тестироваться в 5 состояниях:
  1. *Loading state:* Скелетон или аккуратный индикатор.
  2. *Empty state:* Понятный текст и CTA, когда данных нет.
  3. *Error state:* Объяснение сбоя и кнопка перезагрузки.
  4. *Success state:* Обычный вид с данными.
  5. *Partial / Stale state:* Отображение старых данных во время фонового обновления.

### 83. Строгий TypeScript: Запрет `any`
- Включение `"strict": true` в `tsconfig.json`.
- Категорический запрет типа `any` (использование `unknown` с последующим сужением типов Type Narrowing).
- Использование Discriminated Unions для полиморфных компонентов:
  ```typescript
  type ButtonProps = 
    | { as?: 'button'; onClick: () => void; href?: never }
    | { as: 'a'; href: string; onClick?: never };
  ```

### 84. Визуальное регрессионное тестирование (Playwright Visual Snapshots)
- Автоматическое попиксельное сравнение скриншотов ключевых страниц и компонентов в разных браузерах (Chromium, WebKit, Firefox): мгновенное обнаружение съехавших отступов, поехавших шрифтов и сломанных сеток до деплоя.

### 85. Линтинг и форматирование на pre-commit хуках
- Настройка Husky + lint-staged: при каждом `git commit` автоматически запускается проверка типов (`tsc --noEmit`), линтинг ESLint и форматирование Prettier строго для измененных файлов, предотвращая попадание сломанного кода в репозиторий.

### 86. Изоляция тестов и очистка памяти
- Автоматическая очистка DOM и сброс моков после каждого теста (`afterEach(() => { cleanup(); vi.clearAllMocks(); })`), исключающая сайд-эффекты и ложные срабатывания тестов.

### 87. Contract Testing через OpenAPI / tRPC
- Автоматическая генерация клиентских TypeScript-типов и SDK из схемы бэкенда (OpenAPI / Swagger / tRPC). Изменение типа поля на бэкенде приводит к ошибке компиляции фронтенда в CI до попадания в прод.

### 88. Тестирование отзывчивости верстки (Responsive Viewport Matrix)
- Автоматический прогон E2E-тестов на 4 контрольных разрешениях: 320px (Mobile Small), 375px (Mobile Standard), 768px (Tablet) и 1440px (Desktop).

## Раздел VIII: Инструменты разработчика, сборка и DX (89–100)

### 89. Скорость сборки: Turbopack, Vite и Rspack
- Отказ от медленного устаревшего Webpack в пользу инструментов на базе Rust/Go (Turbopack в Next.js, Vite на esbuild/Rollup, Rspack). Мгновенный горячий перезапуск модулей (HMR $<50$ мс) и ускорение холодной сборки в 5–10 раз.

### 90. Менеджер пакетов pnpm: Изоляция и экономия диска
- Использование pnpm вместо npm/yarn:
  - Хранение пакетов в едином глобальном хранилище на базе жестких ссылок (Hard Links) экономит десятки гигабайт диска.
  - Строгая изоляция `node_modules` (Phantom Dependencies Prevention): проект физически не может импортировать библиотеку, если она не объявлена в его `package.json`.

### 91. Анализ бандла перед релизом (Bundle Analyzer)
- Регулярный запуск `@next/bundle-analyzer`: поиск случайно попавших серверных библиотек в клиентский бандл, обнаружение дублирующихся версий пакетов и неиспользуемых иконочных шрифтов.

### 92. Использование нативных веб-стандартов
- Максимальный отказ от тяжелых внешних утилит в пользу нативного API:
  - Использование нативного `fetch` вместо `axios`.
  - Использование `URL` и `URLSearchParams` вместо `query-string`.
  - Использование `structuredClone()` вместо `lodash.cloneDeep`.
  - Использование `FormData` вместо ручной сборки multipart-запросов.

### 93. Отмена устаревших запросов через `AbortController`
- Каждый асинхронный эффект или поисковый запрос связывается с `AbortSignal`:
  ```typescript
  useEffect(() => {
    const controller = new AbortController();
    fetchData({ signal: controller.signal });
    return () => controller.abort();
  }, [query]);
  ```
- Исключает утечки памяти и отображение неактуальных результатов при быстром наборе текста.

### 94. Безупречный Static Export (`output: 'export'`)
- Настройка проектов, не требующих Node.js на сервере, в режим статического экспорта: генерация чистого HTML/CSS/JS в папку `/out`, готового к мгновенной раздаче через Nginx, S3 или Cloudflare Pages с нулевыми затратами на серверный рантайм.

### 95. DevContainers для мгновенного онбординга команды
- Конфигурация `.devcontainer/devcontainer.json` в репозитории: новый разработчик открывает проект в VS Code / Cursor и за 2 минуты получает готовую изолированную среду с установленной версией Node.js, pnpm, расширениями и базой данных без ручной настройки машины.

### 96. Чистота продакшн-билда (Console & Debug Purge)
- Автоматическое удаление всех `console.log`, `console.debug` и отладочных меток при сборке для production через настройки компилятора (`compiler: { removeConsole: true }` в Next.js).

### 97. Оптимизация OpenGraph и социальных метатегов
- Автоматическая динамическая генерация изображений социальных превью через `@vercel/og` (Satori): создание брендированных карточек для Telegram, Twitter и WhatsApp на лету по JSX-шаблону.

### 98. Политика актуальности браузеров (Browserslist)
- Настройка `browserslist` в проекте: `defaults, not IE 11, not dead`. Исключение сотен килобайт устаревших полифиллов для несуществующих старых браузеров.

### 99. Профилирование производительности (React Profiler & DevTools)
- Запись сессий рендеринга через React Profiler: выявление компонентов, которые рендерятся дольше 16 мс («дроп кадров»), и устранение причин лишних ререндеров с помощью оптимизации пропсов.

### 100. Финальный чеклист качества Staff Frontend инженера (Frontend Excellence Gate)
- Контрольный список для допуска любого фронтенда в релиз:
  - [ ] **Core Web Vitals:** LCP $<2.5$ сек, INP $<200$ мс, CLS $<0.1$ в Lighthouse аудите.
  - [ ] **Доступность:** Навигация работает с клавиатуры (Tab/Enter/Esc), `:focus-visible` виден, нет ошибок по axe-core.
  - [ ] **Темизация:** Используются строго семантические токены CSS-переменных, нет захардкоженных цветов.
  - [ ] **Безопасность:** Пользовательский HTML санитизирован через DOMPurify, внешние ссылки имеют `rel="noopener noreferrer"`.
  - [ ] **Бандл:** Начальный JS на страницу $\le 100$ КБ gzipped, тяжелые компоненты вынесены в динамические импорты.
  - [ ] **Надежность:** Все формы защищены от ботов, мутации оптимистичны с откатом, сетевые запросы имеют AbortController.
  - [ ] **TypeScript:** Проект компилируется с 0 ошибок в strict mode, нет типов `any`.
