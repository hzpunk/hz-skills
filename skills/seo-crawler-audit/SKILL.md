# SEO Crawler Audit (`seo-crawler-audit`)

Скилл для автоматизированного аудита и контроля поисковых краулеров перед релизом и после деплоя. Предотвращает ошибки индексации, пессимизацию сниппетов в выдаче и падение ранжирования из-за таймаутов краулеров.

---

## 1. Регламент и критерии аудита

### Priority 1: Доступность страниц для краулеров (Crawlability & Zero-Downtime)
* **Запрет таймаутов и сбросов соединений**: Поисковые краулеры (Googlebot, YandexBot, Screaming Frog) обходят страницы пачками по 20–50 параллельных запросов.
* **Проверка Live ответов**: Все публичные страницы обязаны стабильно возвращать `HTTP/2 200` с моментальным TTFB (< 300–400 мс).
* **Zero-Downtime при релизах**: Запрещено допускать недоступность страниц в момент `docker compose` перезапусков. При перезапуске контейнеров краулеры не должны получать разрывы соединений.
* **Проверка через CLI**:
  ```bash
  for url in $(curl -s https://example.ru/sitemap.xml | grep -o 'https://[^<]*'); do
    code=$(curl -I -s -o /dev/null -w "%{http_code}" "$url")
    echo "$code $url"
  done
  ```

---

### Priority 2: Стандарты метаданных (Metadata Guardrails)

1. **Meta Title (строго до 60 символов)**:
   * **Длина**: $\le 60$ символов (оптимально 45–55).
   * **Правило фокуса**: Главное ключевое слово («Сайт для...», «Тариф...») ставится в самое начало.
   * **Анти-паттерн**: Заголовки длиннее 60 символов усекаются поисковиками с многоточием (`...`), снижая CTR.

2. **Meta Description (строго 120–160 символов)**:
   * **Длина**: от 120 до 160 символов.
   * **Правило качества**: Конкретные факты, цифры, выгода, наличие призыва к действию (CTA).
   * **Анти-паттерн**: Описания короче 120 символов признаются поисковиками малоинформативными; длиннее 160 символов — обрезаются.

3. **Контроль Noindex**:
   * Разрешенные к индексации страницы **не должны** содержать директиву noindex.
   * Закрытые зоны (`/private`, `/admin`, `/dashboard`, `/login`) обязаны иметь строго подтвержденный единичный noindex (`robots: { index: false, follow: false }` и `Disallow` в `robots.txt`).

4. **Актуальность Sitemap**:
   * Все новые сгенерированные посадочные страницы обязаны автоматически присутствовать в `/sitemap.xml`.
   * Страница `robots.txt` обязана содержать директиву `Sitemap: https://.../sitemap.xml`.

## 2. Скрипт быстрой самопроверки метаданных

Перед коммитом новых страниц проверять длину метатегов:

```javascript
// Проверка длины title и description в каталоге
const fs = require("fs");
const file = fs.readFileSync("src/lib/landing-catalog.ts", "utf8");

for (const m of file.matchAll(/metaTitle:\s*"([^"]+)"/g)) {
  if (m[1].length > 60) console.error(`Title > 60 chars (${m[1].length}): "${m[1]}"`);
}

for (const m of file.matchAll(/metaDescription:\s*"([^"]+)"/g)) {
  if (m[1].length < 120 || m[1].length > 160) {
    console.error(`Desc out of 120-160 (${m[1].length}): "${m[1]}"`);
  }
}
```

---

## 3. Выходной чеклист аудита (Gate Checklist)

- [ ] Все публичные URL из `sitemap.xml` отдают `HTTP 200` при проверке `curl -I`.
- [ ] Длина каждого `metaTitle` $\le 60$ символов с ключевым словом в начале.
- [ ] Длина каждого `metaDescription` строго от 120 до 160 символов.
- [ ] Единственные страницы с `noindex` — строго служебные/приватные (`/private`, `/admin`, `/dashboard`).
- [ ] `robots.txt` доступен и указывает на актуальный `sitemap.xml`.
