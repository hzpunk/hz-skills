# Ролевой стандарт GitHub Issue и декомпозиции вех (`hz-github-roles-standard`)

## Принципы и инварианты

1. **Запрет на бюрократическую инфляцию тикетов:**
   - Категорически запрещено плодить по 7 пустых микро-тикетов на каждую мелкую фичу или баг.
   - Мелкие и связные доработки ведутся в рамках **одного общего Issue** со сквозным ролевым чеклистом:
     - `[ ] @dev`: реализация эндпоинта и миграции БД
     - `[ ] @clo`: юридическое согласование согласия на ПДн (152-ФЗ)
     - `[ ] @pmo`: сбор первой сотни целевых контактов

2. **Декомпозиция вех (Milestones) по доменным стримам:**
   - На уровне крупных вех (M1–M5) задачи разделяются на самостоятельные тикеты только при наличии **независимого и асинхронного Definition of Done (DoD)**.
   - Каждый тикет обязан иметь единый префикс роли в лейблах:
     - `role:dev`: IT-разработка, архитектура, бэкенд, фронтенд, багфиксы.
     - `role:pmo`: Сбор данных, лидогенерация, браузерный парсинг (Playwright MCP) и аутрич.
     - `role:clo`: Юридический комплаенс, 152-ФЗ, оферта, реестр РКН, проверка Минюста.
     - `role:cmo`: Маркетинг, позиционирование, дистрибуция, рассылки, контент-план.
     - `role:cpo`: Продукт, CJM, экраны интейка, логика модальных окон, UX-эвристики.
     - `role:secops`: Защита от ботов, Turnstile, ASN-блокировки, криптография токенов.
     - `role:cfo`: Монетизация, юнит-экономика, биллинг, платежные шлюзы (YooKassa).

3. **Инвариант закрываемого артефакта (DoD):**
   - Запрещены статические «вечные» тикеты без дедлайна (типа «Тикет для PMO»).
   - Issue считается выполненным только при предъявлении артефакта: PR со 100% тестами, подписанный ADR, спарсенный и очищенный CSV-файл лидов в Notion, накатанная миграция.

4. **Исполнители и автономные боты:**
   - Каждая роль может исполняться живым инженером (`@hzpunk`, `@VladislavSCV`) либо автономным субагентом через `boss-orchestrator.py` и бесплатные CLI-раннеры (Gemini CLI / Goose / Vibe).
